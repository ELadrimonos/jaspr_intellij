# Changelog

## [Unreleased]

## [1.3.0] - 2026-10-30
### Added
- Compatibility with Jaspr 0.24 (tested against `0.24.0-beta.0`).
- UI guides for component trees ([schultek/jaspr#914](https://github.com/schultek/jaspr/issues/914)): lines in the editor connect each component to its children (`div([...])`, `children:`, `child:` and `body:` arguments, including `if`/`for`/spread elements), in `build` methods and functions returning a `Component`. Platform indent guides in the same column are hidden so they don't overlap. Toggle in **Settings | Languages & Frameworks | Jaspr**.
- **Jaspr Hot Reload** / **Jaspr Hot Restart** actions in the Run/Debug tool window toolbar, which send `client.restart` to the running daemon. Hot Reload is only offered with jaspr_cli ≥ 0.24 (older CLIs only support restarts), and a failed reload/restart is reported in the console.
- "Auto action (on save)" run option (`refresh`, `reload`, `restart`, `none`), mapped to `--auto` on jaspr_cli ≥ 0.24 and to `--mode` on older versions.
- "Install Jaspr AI skills" checkbox in the New Project wizard (off by default; passes `--[no-]skills` on jaspr_cli ≥ 0.24).
- Hot reload and graceful shutdown through Melos. With Melos ≥ 7.8.0, generated scripts use `run:` with `stdio: inherit`, so the daemon receives stdin. Existing generated scripts are upgraded when the project opens.
- When a component is rendered from several scope roots, clicking its scope hint opens a chooser instead of jumping to the first root.
- "Open DevTools on debug" run option. DevTools no longer opens in the browser on every Debug start; the URL is still printed to the console.
- Inspection for Jaspr 0.24's native CSS nesting: nested `css()` rules whose selector appends to the parent, like `css('.button', [css('&-active')])`, no longer produce `.button-active`. A quick fix moves the rule out next to its parent as `css('.button-active')`. Only runs when the package resolves jaspr ≥ 0.24.

### Fixed
- Stopping a Jaspr run configuration no longer freezes the IDE for 1.5 s. The daemon gets `daemon.shutdown` and up to 2 s to exit, on a background thread, before it is killed.
- Stopping a daemon that doesn't handle `daemon.shutdown` (e.g. through a `melos exec` script) no longer leaves the jaspr server and its Dart VM service running in the background, holding port 8181 and breaking the next run. The whole process tree is now killed.
- The "Jaspr version mismatch" warning is now an editor banner on each Dart file, checked against that file's own package. In a monorepo, a module on a different jaspr version than the installed jaspr_cli is flagged even when it isn't the first Jaspr package. The check uses the version resolved in `pubspec.lock` (including a workspace's root lockfile, falling back to the `pubspec.yaml` constraint) and compares major.minor only, so patch differences no longer warn. It replaces the balloon shown when the project opened.
- `jstyls` live template now generates a `static` `@css` getter (jaspr_builder rejects non-static class members) and is only offered inside a class body. The new `jstylsg` template creates top-level global styles.
- "Convert to Jaspr" no longer inserts jaspr_cli's "Update available!" box into the generated file, and keeps the converted code's indentation (uses `convert-html --json`). Large HTML files are passed through a temp file instead of the command line.
- Jaspr Build/Doctor/Clean and "Convert to Jaspr" now use the Jaspr package directory in Dart workspace/Melos monorepos instead of the opened root.
- Component-scope hints no longer flicker or go missing while `scopes.json` reloads. Scope data is now swapped in one step and is safe to read from any thread.
- Component-scope hints in workspaces with several Jaspr apps. Each app's `scopes.json` is now watched, instead of only the first app's. A file inside an app only shows that app's scopes. A file in a shared package shows the scopes of every app that renders it, labelled by app (e.g. "Client Scope · web, admin"), and the root chooser names the app of each root. Apps are re-discovered when a `pubspec.yaml` or `melos.yaml` changes.
- "Jaspr package" run option to choose which app of a workspace to serve. Without a Melos script, the daemon now runs in that package (by default the project's first Jaspr package) instead of the opened root, so plain Dart pub workspaces without Melos can run their apps. The entry point and `--dart-define-from-file` paths are re-based onto the package.
- Workspace members declared with globs (`packages/*`, `apps/**`) in the pub `workspace:` field, and Melos 6 `packages:` globs in `melos.yaml` without a pub workspace, are now detected.
- Melos scripts generated by the plugin used `packageFilters.packageName`, which Melos ignores. The daemon ran in every workspace package, and each output line was prefixed with `[package]: `, so the console showed raw JSON. Scripts now use `scope`, existing generated scripts are migrated when the project opens, and the console tolerates the Melos prefix.

### Changed
- No upper IDE version limit (`until-build`): the plugin installs on new IntelliJ releases without an update. Verified against 2025.1 – 2026.3.
- Hot Reload/Restart actions are hidden for Melos scripts that don't forward stdin (`exec:` scripts on Melos < 7.8.0).
- Saving a file during `serve` no longer reparses every open Dart file. Only editors whose component scopes actually changed are refreshed, and the `scopes.json` watcher runs on the shared scheduler instead of a dedicated thread.
- Opening a project runs `jaspr --version` once instead of three times. "Update Jaspr CLI" now refreshes the cached CLI version.
- Project setup only touches the module that contains the Jaspr package, and no longer commits an unchanged module model on every project open.
- Plugin description and notification texts updated; user-visible strings moved to the message bundle.
- Integration tests use an isolated `PUB_CACHE` (`build/test-pub-cache`) with a pinned jaspr_cli, so running them no longer changes your global jaspr_cli or melos.
- "Web port" and "Proxy port" are ignored on jaspr_cli ≥ 0.24, which removed them and now picks ports automatically. A warning is printed if either is set.
- Console output understands the new jaspr_cli 0.24 log format: tags, warning and error levels, `[BUILDER]` folding, and the colored startup banner.

## [1.2.0] - 2026-08-25
### Added
- Dart/Melos workspace detection: the plugin now recognizes when a project is part of a Dart pub workspace or a Melos-managed monorepo, walking up from a member package to find the workspace root.
- Automatic, idempotent injection of a delimited `melos.scripts` entry (in `melos.yaml` or the root `pubspec.yaml`) that runs `jaspr daemon` scoped to a package — merges safely alongside scripts the user or `melos bootstrap` already declared, without clobbering them.
- New "Melos script" field in the Jaspr Run/Debug Configuration editor (dropdown of known scripts, editable) — when set, the daemon is launched via `melos run <script>` instead of directly, with all other run-configuration flags (port, mode, dart-defines, etc.) forwarded through.
- New "Create Melos Script..." action under **Tools → Jaspr**, for registering an additional Jaspr app's script in a monorepo with more than one Jaspr package.
- Proactive console warning when a run configuration has no "Melos script" set inside a detected workspace, before the daemon fails.

### Fixed
- Fixed project creation issue where generated files were not copied if the CLI failed on dependency constraints (e.g. `pub get` errors)[cite: 4].
- Fixed failing unit/integration test suite.
- Fixed `--input` and `--dart-define-from-file` paths being resolved against the workspace root instead of the target package directory when running via a Melos script, causing "Specified entry point ... does not exist" failures.

### Changed
- Added support and compatibility for IntelliJ IDEs version 2026.2.x.

## [1.1.0] - 2026-05-04
### Added
- Introduced `JasprLegacy` annotation to isolate legacy daemon-based functionality.
- Updated tests to support Jaspr 0.22.4 and 0.23.0.

### Changed
- Updated compatibility with Jaspr 0.23.0.
- Switched HTML conversion to CLI-based implementation for Jaspr >= 0.23.0.
- Maintained backward compatibility with pre-0.23.0 versions using the tooling daemon.

## [1.0.0] - 2026-04-16
### Added
- Initial stable release of the plugin.
- Run configuration to execute `jaspr daemon` with full lifecycle management (graceful shutdown and Chrome cleanup).
- Formatted console output with colour-coded logs (CLI, builder, server, client).
- Integration with `jaspr tooling-daemon`.
- Inlay hints showing server/client component rendering context.
- HTML to Jaspr conversion via context menu for `.html` files.
- Automatic Dart file generation with `StatelessComponent` scaffolding.
- New Project Wizard for Jaspr applications.
- File templates for `StatelessComponent`, `StatefulComponent`, and `InheritedComponent`.
- Live code snippets: `stlessc`, `stfulc`, `inhc`, `jhtml`, `jtext`, `jstyls`, `jevt`, `jclick`.
- Maintenance actions: Clean and Doctor.
- Tooling daemon status monitoring.
- Version mismatch detection between `jaspr_cli` and `pubspec.yaml`.
- CLI update action from the IDE.
- Inspections for common issues (e.g. multiple scope annotations).
- Debugger attachment support for server and client VM services.
- Annotation inspection (e.g. Cannot have multiple components annotated with @client in a single library.)
